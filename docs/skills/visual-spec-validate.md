# visual-spec-validate — 설명

`skills/visual-spec-validate/SKILL.md`는 에이전트가 실행 시 참조하는 지시문이다.
사람이 이 스킬이 뭘 하는지 파악하려면 이 문서를 본다.

## 이 스킬이 하는 일

`validateVisualSpec`이 낸 `issues`를 해석하고, 어느 값을 어떻게 고치면 되는지 짚어준다.
`code`별 실패 분류표는 `SKILL.md` 본문에 있다 — `examples/invalid/` 8개와 1:1로 대응한다.

### 왜 별도 스킬이 필요한가

`issues` 배열만 보고는 알 수 없는 것들이 있어서다. 검증기는 무엇이 틀렸는지 알려주지만,
**그 출력을 어떻게 읽어야 하는지는 알려주지 않는다.** 모르면 엉뚱한 곳을 고치게 되는
함정이 최소 세 가지 있다.

**`code: "schema"`의 `message`는 상수다.** 전부 "JSON 스키마의 구조 규칙을 위반했습니다"로
똑같이 나온다. 어느 필드가 문제인지에 대한 정보가 `message`에 아예 없다. 볼 것은 `path`뿐인데,
`message`를 읽고 단서를 찾으려다 시간을 쓰기 쉽다.

**이슈 개수는 심각도가 아니다.** 노드 하나가 틀리면 스키마의 `oneOf` 분기마다 이슈가 생겨
7~10개가 한꺼번에 쏟아진다. 실수는 보통 하나다. 개수를 보고 "많이 망가졌다"고 판단하면
틀린다. `path`를 중복 제거하고 그 노드 하나만 보면 된다.

**`root-missing`이나 `cycle`이 있으면 `orphan-node` 검사가 생략된다.** 출발점이 없거나
순환이 있으면 모든 노드가 도달 불가로 잡혀 진짜 원인이 잡음에 묻히기 때문이다. 문제는
이 생략이 조용하다는 것이다. 고아 노드가 **없다고 보고된 게 아니라 아직 안 본 것**인데,
출력만 보면 구분이 안 된다. 루트나 순환을 고치고 재검증하면 그때 나타난다.

같은 이유로 스키마 검증이 실패하면 구조 검사는 아예 돌지 않는다. 그래서 고칠 때마다 이슈가
줄기는커녕 새로 나타나는 일이 생기는데, 이게 정상이다. 완료 기준은 이슈가 줄었다는 것이
아니라 `valid: true`다.

## 언제 실행되는가

`skills/visual-spec-validate/SKILL.md`의 `description`에 적힌 조건과 매칭될 때 자동으로
붙거나, 사용자가 직접 이름을 불러 실행한다.

- "검증 실패했는데 뭐가 문제야", "valid가 false로 나와"
- "루트에서 도달할 수 없습니다", "자식 노드가 nodes에 없습니다" 같은 에러 문구를 그대로 가져올 때
- "VisualSpecValidationError 떴어"
- 아직 실패하지 않았어도 "스펙 검증해줘", "이 JSON 맞게 쓴 건지 확인해줘"처럼 검증을
  돌려달라는 요청
- [visual-spec-authoring](./visual-spec-authoring.md)에서 스펙을 다 쓰고 검증에 실패했을 때
  이어서

## 어떻게 쓰는가

1. 실패한 스펙과 `issues`를 준다. 스펙 경로만 줘도 된다.
2. `code: "schema"`가 하나라도 있으면 그것부터 잡는다. `path`를 중복 제거해 대상 노드를 좁힌다.
3. 그 노드를 정본 스키마의 `required`, `additionalProperties`와 대조해 고친다. 정의를 외워서
   판단하지 않는다.
4. 고칠 때마다 재검증한다. 가려져 있던 이슈가 새로 나타나면 이어서 잡는다.
5. `valid: true`가 될 때까지 반복한다.

## 이 스킬이 하지 않는 것

- 자동 수정. 무엇을 어떻게 고칠지 짚어주지만 사용자 확인 없이 스펙을 덮어쓰지 않는다
- 한 번에 전부 잡아내기 (검사 단계가 앞 단계 성공에 의존해서 구조적으로 불가능하다)
- 스키마 정의 암기 → [visual-spec-docs](./visual-spec-docs.md)가 정본 찾는 법을 준다
- 스펙을 처음부터 새로 쓰기 → [visual-spec-authoring](./visual-spec-authoring.md)이 맡는다

`code`별 실패 분류표와 수정 절차는 `skills/visual-spec-validate/SKILL.md` 본문을 본다.
어느 스킬로 가야 할지 모르겠으면 [visual-spec](./visual-spec.md) 허브로 돌아간다.
