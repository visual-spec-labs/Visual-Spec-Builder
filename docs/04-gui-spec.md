# 04. GUI 명세

> 출처: ClickUp 팀 문서 `GUI 내용 정리`, `PRD 1차` 2·9장
> 홈화면 절은 2026-08-15 설계 논의에서 새로 확정했다. 근거는 [설계 문서](superpowers/specs/2026-08-15-docs-restructure-and-home-screen-design.md) 참고.

이 문서는 에디터 GUI의 구조와 기능을 정의한다. **GUI 자체의 구현 문서가 아니라, 어떤 데이터를 생성하고 수정할지 판단하기 위한 기준**이다. 스키마 설계 시에는 특히 캔버스의 노드 계층, 레이어 트리의 부모-자식 구조, 세부설정 패널의 Layout · Background · Font · Border 항목, Frame 및 Text 도구를 참고한다.

File · View · Export · Version History 등은 에디터 기능이며 화면 데이터 스키마와 직접 연결하지 않는다.

**상태 표기 범례**

| 마커 | 의미 |
|---|---|
| ✅ | MVP 포함 |
| ➕ | 추가 기능 (MVP 이후) |
| ⚠️ | MVP 제외 |
| ❓ | 미확정 — [open-questions.md](open-questions.md) |

## 2. 홈(진입) 화면

`npx visual-spec` 실행 후 `localhost:4173`에서 처음 만나는 화면이다.

> **2026-09-01 — 이 절의 전제가 바뀌었다 (#60)**
>
> 아래 설계는 **저장 단위를 "화면 1개"로 두고** 화면 카드를 나열한다. 스키마 v0.2에서 저장 단위가 **프로젝트 1개(페이지 여러 개)**가 되었으므로, 목록에 놓이는 것은 화면이 아니라 프로젝트다. 페이지 전환은 홈으로 나가지 않고 에디터 안 레이어 트리에서 한다(#63).
>
> **재설계는 아직 하지 않았다.** 카드에 무엇을 보일지(대표 페이지 미리보기? 페이지 수?), 정렬 기준, `+ 새 화면`이 `+ 새 프로젝트`가 되는지는 GUI 결정이라 스키마 변경과 같은 PR에서 정하지 않는다. 별도 이슈로 다룬다.
>
> 아래 내용은 그때까지 "화면"을 "페이지"로 읽으면 대체로 통한다. 다만 목록의 단위만은 프로젝트다.

### 설계 기준

PRD 2장은 진입 시 세 갈래 선택지를 제시하도록 되어 있다. 이를 그대로 두면 저장된 화면이 늘어날수록 매번 선택을 강요받고, "기존 화면 불러오기"를 고른 뒤 다시 목록을 봐야 한다.

따라서 **화면 목록을 기본 상태로 두고, 세 갈래 선택지는 목록이 비었을 때만 보여준다.** PRD 원안의 의도는 유지하면서 반복 클릭을 없애는 구성이다.

이 결정의 실질적 근거는 현재 MVP의 유일한 작업 항목이 *"로그인 화면 JSON을 에디터에서 열고 … React 코드로 출력한다"*라는 점이다. 목록 우선 구조에서는 이 경로가 클릭 한 번으로 끝난다.

### 상태 1 — 저장된 화면이 있을 때 (기본) ✅

```
┌──────────────────────────────────────────────┐
│ Visual Spec Studio            [+ 새 화면]     │
│ C:\project\my-app                            │
├──────────────────────────────────────────────┤
│ 화면 3개                        최근 수정순 ▾ │
│                                              │
│ ┌────────┐  ┌────────┐  ┌ ─ ─ ─ ┐            │
│ │ [미리보기]│  │ [미리보기]│  │   +   │            │
│ ├────────┤  ├────────┤  │ 새 화면│            │
│ │ Login  │  │Dashboard│  └ ─ ─ ─ ┘            │
│ │390×844 │  │1440×900 │                      │
│ │ 2일 전  │  │ 5일 전  │                      │
│ └────────┘  └────────┘                       │
└──────────────────────────────────────────────┘
```

| 요소 | 내용 |
|---|---|
| 헤더 | 제품명, 현재 프로젝트 경로, `+ 새 화면` 버튼 |
| 목록 | 화면 카드 그리드. 기본 정렬은 최근 수정순 |
| 카드 | 미리보기 · 화면 이름 · 크기 · 수정 시각 |
| 마지막 칸 | 새 화면 추가 자리 (점선) |

### 상태 2 — 첫 실행 (목록이 빔) ✅

```
┌──────────────────────────────────────────────┐
│ Visual Spec Studio                           │
│ C:\project\my-app                            │
├──────────────────────────────────────────────┤
│           첫 화면을 만들어 봅시다              │
│          어떻게 시작하시겠습니까?              │
│                                              │
│      ┌──────────────────────────┐            │
│      │ 자연어로 초안 만들기        │            │
│      │ 설명을 입력하면 구조를 생성  │            │
│      ├──────────────────────────┤            │
│      │ 빈 캔버스에서 시작          │            │
│      │ 직접 요소를 배치            │            │
│      ├──────────────────────────┤            │
│      │ 기존 화면 불러오기          │            │
│      │ JSON 파일을 엽니다          │            │
│      └──────────────────────────┘            │
└──────────────────────────────────────────────┘
```

PRD 2장의 세 갈래 선택지가 여기로 들어간다. 목록이 채워지면 이 화면은 사라지고, 선택지는 `+ 새 화면` 버튼 뒤로 물러난다.

세 선택지는 배타적인 모드가 아니다. 어떤 방식으로 시작하든 이후에는 자연어와 직접 조작을 자유롭게 섞을 수 있다.

### 데이터 출처 ✅

목록에 필요한 값은 **모두 기존 스키마와 파일 시스템에 존재한다. 스키마 변경이 필요 없다.**

| 표시 항목 | 출처 |
|---|---|
| 화면 이름 | `screen.name` (예: `"Login"`) |
| 크기 | `screen.size` (예: `390 × 844`) |
| 수정 시각 | `.visual-spec/specs/*.json` 파일 mtime |
| 미리보기 | 스펙 JSON에서 즉석 렌더 (아래 참고) |

### 미리보기 렌더링 ✅

카드의 미리보기는 **스펙 JSON을 읽어 축소 렌더한다.** 캡처 이미지를 저장하지 않는다.

이유는 두 가지다.

- 항상 최신 상태다. 스펙과 이미지가 어긋날 일이 없다
- MVP 폴더 구조(`specs / generated / preview / assets / runtime`)에 스크린샷을 둘 자리가 없다. PRD 초안의 `.visual-spec/screenshots/`는 MVP에서 빠졌다

캔버스 렌더러는 어차피 만들어야 하므로 그 구현을 축소 모드로 재사용한다. MVP 노드 종류(Frame · Text)만 그리면 되므로 부담이 크지 않다.

### 미확정 ❓

- 화면 이름과 파일명의 관계 — `screen.name`과 `specs/*.json` 파일명을 동기화할지, 독립적으로 둘지
- 목록 항목의 액션 범위 — 열기 외에 복제 · 삭제 · 이름 변경 중 무엇을 MVP에 넣을지
- 프로젝트 개념의 존재 여부 — 화면만 나열할지, 화면을 묶는 상위 단위를 둘지

## 3. 에디터 전체 레이아웃

화면은 크게 5개 영역으로 구성된다.

| 영역 | 위치 | 역할 |
|---|---|---|
| 상단 메뉴바 | 최상단 | File / View / Help |
| 레이어 트리 | 좌측 | 화면(노드) 계층 구조 탐색 |
| 캔버스(결과·수정 화면) | 중앙 | GUI 생성 결과 확인 및 직접 편집 |
| 세부설정 패널 | 우측 | 선택 요소의 속성 편집 |
| 도구 모음 | 하단 | 선택/생성 도구 전환 |

PRD 9장은 여기에 더해 하단 AI 입력창과 실행 상태 영역을 제시한다.

```
┌────────────────────────────────────────────────────────┐
│ 프로젝트 / 화면 선택 / Undo / Redo / 저장 / 구현 실행      │
├──────────┬──────────────────────────┬──────────────────┤
│ 요소     │                          │ 속성              │
│ 컴포넌트  │         캔버스            │ 레이아웃           │
│ 화면 트리 │                          │ 스타일 / 반응형    │
├──────────┴──────────────────────────┴──────────────────┤
│ AI 입력: 선택한 요소를 어떻게 변경할까요?                  │
├────────────────────────────────────────────────────────┤
│ 변경 내역 / 구현 티켓 / Claude Code 실행 상태             │
└────────────────────────────────────────────────────────┘
```

AI 입력창은 단순 채팅창이 아니라 **현재 선택 상태와 결합된 명령창**이다. 적용 범위 표시 규칙은 [03-user-flow.md](03-user-flow.md) 참고.

## 4. 상단 메뉴바

### 4.1 File

| 기능 | 설명 | 비고 |
|---|---|---|
| New / Open | 새 프로젝트 생성, 기존 파일 열기 | Open은 폴더 단위로 저장된 프로젝트를 불러옴 |
| Save / Save as | 작업 내용 저장, 다른 이름으로 저장 | 프로젝트 폴더 형태로 저장 |
| Import / Export | 이미지·코드·디자인 파일 가져오기 / 최종 결과물 내보내기 | Export 시 결과물이 폴더로 생성되고 zip으로 추출 |
| Version History | 과거 작업 히스토리 확인 및 복구 | ❓ Undo와의 관계, File 메뉴 포함 여부 논의 필요. MVP 제외 가능성 |

### 4.2 View

| 기능 | 설명 |
|---|---|
| Zoom In/Out | 퍼센트 단위 확대/축소, 마우스 휠 = 화면 이동, Ctrl+휠 = 확대/축소 |
| Fit to Screen | 화면 크기에 맞게 캔버스 자동 조정 |
| Show/Hide Grid | 캔버스 그리드(격자) 표시 여부 |
| Panels/Sidebars | 좌우 패널 표시 여부 |

### 4.3 Help ⚠️

Documentation / Keyboard Shortcuts / Release Notes / Support. **MVP 범위에서 제외한다.**

## 5. 캔버스

중앙 캔버스는 생성 결과를 확인하고 직접 수정하는 핵심 작업 공간이다.

- 현재 화면명 표시
- 줌 인/아웃 컨트롤
- 캔버스 작업 영역
- 선택 요소 테두리 표시
- 드래그·리사이즈 핸들
- 정렬 가이드(스냅 라인)
- 빈 화면 안내 문구
- 생성 결과 미리보기
- 실행 상태 표시
- 마우스 우클릭 컨텍스트 메뉴 — Composition

### Composition 컨텍스트 메뉴

| 기능 | 설명 |
|---|---|
| Group / Ungroup | 여러 레이어를 하나로 묶거나 해제. 복잡한 구조 생성의 핵심 |
| Component / Asset | 자주 쓰는 요소를 재사용 부품으로 전환 |
| Layer Order | 레이어 앞/뒤 순서 제어. Bring to Front / Send to Back |

## 6. 레이어 계층 구조 (좌측 트리)

- 화면명 표시
- 노드 계층 트리(부모-자식 구조)
- 펼치기/접기 버튼
- 노드 작업 아이콘
- 선택 상태 하이라이트 표시
- 노드 추가 버튼
- 잠금 토글
- 드래그로 순서 변경

### 트리 하단 편집 컨트롤

현재 선택 요소 표시, 요소 추가/삭제, 테마·사이즈 변경, 스타일 변경 → 적용/Export, 반응형 설정, 기능(동작) 정의, 되돌리기.

❓ 새 레이어 명명 규칙과 선택 방식은 미확정이다.

### 예시 트리 구조

```
DashboardPage
├── Sidebar
│   ├── Logo
│   ├── Navigation
│   └── UserProfile
└── Main
    ├── Header
    └── Content
        ├── MetricGrid
        └── ProductTable
```

## 7. 세부설정 패널 (우측)

| 속성 그룹 | 세부 항목 |

| Shadow | x, y, blur, spread, color |

## 8. 도구 모음 (하단)

## 9. 정리 요약 — MVP vs 추가 기능

| 구분 | MVP 포함 | MVP 제외 / 추가 기능 |
|---|---|---|
| 화면 | 홈(목록 + 빈 상태), 에디터 | - |
| 메뉴바 | File, View | Help |
| File 세부 | New/Open, Save/Save as, Import/Export | Version History(논의 필요) |
| 도구 | Select, Frame, Text, Hand | Image, Shape/Pen |
| 편집 패널 | 레이어 트리, 세부설정, Composition | - |

미확정 항목 전체 목록은 [open-questions.md](open-questions.md)에 있다.
