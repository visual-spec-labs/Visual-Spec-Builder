# 문서 재편 및 홈 화면 설계

- 날짜: 2026-08-15
- 범위: 문서만. 코드 변경 없음

## 배경

기획 원본이 ClickUp 팀 문서에 있고 저장소 `docs/`에는 그 일부만 파생되어 있었다. 두 곳의 서술이 어긋난 채로 남아 있어 범위 판단의 기준이 불분명했다. 또한 PRD 2장의 진입 화면이 저장소 문서에 아예 없었다.

## 발견한 모순

정리 과정에서 저장소 문서와 MVP 문서가 정면으로 충돌하는 지점 두 개를 찾았다.

| 쟁점 | `PROJECT_OVERVIEW.md` | `Visual Spec Builder MVP` |
|---|---|---|
| 기존 프로젝트 | "대상 React 프로젝트 **분석**" 단계 존재 | 구조를 "분석하거나 변경하지 **않고**" 독립 작업공간 생성. 폴더·라우터·공통 컴포넌트 분석이 *필요하지 않다*고 명시 |
| 결과 확인 | "결과 화면 확인" 단계 존재 | 해당 절이 **취소선 처리** (React Preview `localhost:4174` 제외) |

**결정:** MVP 문서가 더 최신이자 범위 확정본이므로 MVP 기준으로 통일한다. 두 항목 모두 정정 이력을 본문에 남겼다.

## 결정 1 — `docs/` 를 읽는 순서대로 재편

새 팀원이 위에서부터 순서대로 읽으면 전체가 파악되는 구조로 바꿨다.

| 파일 | 출처 |
|---|---|
| `01-overview.md` | 기존 `PROJECT_OVERVIEW.md` + PRD 1차 도입부 |
| `02-mvp-scope.md` | ClickUp `Visual Spec Builder MVP` |
| `03-user-flow.md` | PRD 1차 2~17장 |
| `04-gui-spec.md` | 기존 `gui-spec.md` + 홈 화면 절 신규 |
| `05-schema.md` | 기존 `VISUAL_SPEC_SCHEMA_V0.1.md` |
| `references.md` | ClickUp `정리해본거`, `참고 사이트` |
| `open-questions.md` | 각 문서의 ❓ 항목 집약 |

**검토한 대안**

- *기존 파일명 유지, 내용만 보강* — diff는 깨끗하지만 읽기 순서 문제가 그대로 남는다
- *단일 `SPEC.md` 통합* — 검색은 편하지만 분량이 커지면 부분 수정과 동시 편집이 어려워진다

`references.md`를 별도로 둔 이유는 오픈소스 조사 2페이지가 01~05 어디에 들어가도 읽는 흐름을 끊기 때문이다.

**원칙:** ClickUp이 원본, 저장소가 작업 기준. 이번 작업에서 ClickUp 문서는 건드리지 않고, 각 문서 상단에 출처 페이지를 표기해 대응 관계를 남긴다.

## 결정 2 — 홈(진입) 화면은 목록 우선

### 선택지

| 안 | 구조 |
|---|---|
| A | PRD 원안. 세 갈래 선택지를 동등하게 제시 |
| **B (채택)** | 저장된 화면 목록이 기본, `+ 새 화면` 버튼 하나 |
| C | 큰 자연어 입력창이 중앙, 나머지는 보조 |

### 채택 근거

현재 MVP의 유일한 작업 항목은 *"로그인 화면 JSON을 에디터에서 열고, 화면을 표시하고, 버튼 문구를 수정한 뒤, 저장하고, React 코드로 출력한다"*이다.

- A는 이 경로에 클릭이 두 번 필요하다 (선택지 → 목록)
- C는 자연어 생성을 앞세우는데, 지금 검증하려는 것은 자연어가 아니라 기존 JSON 열기다
- B는 클릭 한 번으로 끝나고, 화면이 늘어날수록 유리해진다

### A안을 버리지 않았다

PRD의 세 갈래 선택지는 **빈 상태 화면**으로 옮겼다. 화면이 하나도 없을 때만 시작 방식을 묻고, 목록이 채워지면 선택지는 `+ 새 화면` 버튼 뒤로 물러난다. 원안의 의도는 지키면서 반복 클릭을 없앤다.

PRD가 "어떤 방식으로 시작해도 이후에는 자연어와 직접 조작을 자유롭게 섞을 수 있다"고 명시하므로, 이 선택은 기능 차이가 아니라 **무엇을 앞에 둘 것인가**의 문제다.

## 결정 3 — 미리보기는 즉석 렌더

카드의 미리보기는 스펙 JSON을 읽어 축소 렌더한다. 캡처 이미지를 저장하지 않는다.

- 항상 최신이다. 스펙과 이미지가 어긋날 일이 없다
- MVP 폴더 구조(`specs / generated / preview / assets / runtime`)에 스크린샷을 둘 자리가 없다. PRD 초안의 `.visual-spec/screenshots/`는 MVP에서 빠졌다
- 캔버스 렌더러는 어차피 필요하므로 축소 모드로 재사용한다. MVP 노드 종류가 Frame · Text뿐이라 부담이 작다

**검토한 대안:** 저장 시 PNG 캐시. 목록은 빨라지지만 폴더 구조에 디렉터리를 추가해야 하고 스펙과 이미지가 어긋날 수 있다.

## 스키마 영향 — 없음

홈 목록에 필요한 값이 모두 기존 스키마와 파일 시스템에 존재한다.

| 표시 항목 | 출처 |
|---|---|
| 화면 이름 | `screen.name` |
| 크기 | `screen.size` |
| 수정 시각 | `.visual-spec/specs/*.json` mtime |
| 미리보기 | 스펙 JSON 즉석 렌더 |

`examples/login-screen.json`으로 확인했다. **스키마 v0.1 변경이 필요 없다.**
