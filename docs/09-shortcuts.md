# 09. 단축키와 캔버스 조작

Visual Spec Builder 편집기에서 지금 **실제로 동작하는** 것만 적는다.
계획이나 제안은 여기 넣지 않는다 — 문서에 있는데 안 되면 버그 신고가 된다.

배치는 피그마를 따랐다. 같은 일을 하는 키는 같은 자리에 있어야 손이 기억한다.

> **맥에서는 `Ctrl` 자리에 `Cmd`를 쓴다.** 아래 표의 `Ctrl`은 전부 `Ctrl/Cmd`다.
> `Alt`는 맥에서 `Option`이다.

---

## 도구

| 키 | 도구 |
|---|---|
| `V` | Select — 고르기 |
| `H` | Hand — 손(팬) |
| `F` | Frame — 프레임 만들기 |
| `T` | Text — 텍스트 만들기 |

`F`·`T`로 만들면 **곧바로 Select로 돌아온다**(피그마와 같은 흐름).

### 스페이스 임시 팬

`Space`를 **누르고 있는 동안만** 손 도구가 되고, 떼면 쓰던 도구로 돌아온다.
프레임을 그리다 화면만 살짝 옮기고 다시 그릴 때 흐름이 끊기지 않는다.

`H`(고정 전환)와 `Space`(임시)가 둘 다 손 도구인 것은 피그마와 같다.

> **한/영 전환에 영향받지 않는다.** 키보드 레이아웃이 아니라 **물리 키 위치**
> (`event.code`)로 판정하기 때문이다. 한글 상태에서 `V`를 눌러도 도구가 바뀐다.

---

## 보기

| 키 | 동작 |
|---|---|
| `Ctrl` + `+` | 확대 (25% 눈금) |
| `Ctrl` + `-` | 축소 |
| `Ctrl` + `0` | 100%로 |
| `Shift` + `1` | 화면에 맞추기 — 문서 위로 올라간다 |
| `Ctrl` + 휠 | 확대·축소 — **커서 기준** |

- 휠 줌은 **커서 밑 지점이 제자리에 남는다.** 확대해도 보던 곳을 놓치지 않는다.
- 단축키 줌은 **뷰포트 한가운데**가 기준이다(커서 위치라는 개념이 없다).
- 확대율은 **25% ~ 400%**다.

`Ctrl+0`·`Ctrl+-`는 브라우저 페이지 줌이기도 하지만 편집기가 가로챈다.
**단, 입력칸 안에서는 브라우저에 넘긴다.**

---

## 이동(팬)

| 조작 | 동작 |
|---|---|
| 휠 / 트랙패드 | 세로 스크롤 (브라우저 기본) |
| `Space` + 드래그 | 팬 |
| **가운데 버튼 드래그** | 팬 — **도구와 무관하게 언제나** |
| `H` 로 바꾼 뒤 드래그 | 팬 |

가운데 버튼은 무엇을 그리는 중이든 쓸 수 있다. 손을 떼지 않고 화면을 옮기려는 것이다.

---

## 선택

| 조작 | 동작 |
|---|---|
| 클릭 | **최상위 조상** 선택 (root 바로 아래) |
| `Ctrl` + 클릭 | **커서 밑 노드** 선택 (상세 지정) |
| `Esc` | 선택 해제 |
| `Delete` · `Backspace` | 선택 노드 삭제 |

### 왜 클릭하면 안쪽이 아니라 바깥이 잡히나

피그마와 같은 규칙이다. **깊이가 아니라 "무엇을 하나의 덩어리로 볼 것인가"**로
정해진다. 카드 안의 글자를 클릭했을 때 글자가 잡히면 카드를 통째로 옮길 수가 없다.

안쪽을 바로 잡고 싶으면 `Ctrl`을 누른 채 클릭한다.

---

## 편집

| 키 | 동작 |
|---|---|
| `Ctrl` + `Z` | 실행 취소 |
| `Ctrl` + `Shift` + `Z` | 다시 실행 |
| `Ctrl` + `Y` | 다시 실행 (윈도우 관례) |
| `Delete` · `Backspace` | 선택 노드 삭제 |

`Ctrl+Y`는 **윈도우 전용**이다. 맥의 `Cmd+Y`에는 대응하는 관례가 없어 건드리지 않는다.

`Ctrl+Backspace`(앞 단어 삭제)와 `Alt+Backspace`(실행 취소)는 **노드 삭제로 받지
않는다.** 글자를 지우려다 노드가 사라지면 안 되기 때문이다.

입력칸 안에서는 `Ctrl+Z`도 가로채지 않는다 — 브라우저의 텍스트 편집 되돌리기가
그대로 동작해야 한다. 여기서 가로채면 "방금 친 글자"가 아니라 "직전 노드 편집"이
되돌아간다.

## 입력칸에서는 전부 물러선다

`input` · `textarea` · `select` · 편집 중인 레이어 이름 안에서는 위 단축키가
**하나도 동작하지 않는다.** 그 자리에서는 글자가 먼저다.

| 상황 | 결과 |
|---|---|
| 레이어 이름에 `Frame` 입력 | 도구가 안 바뀐다 |
| 텍스트에 띄어쓰기 | 팬이 안 된다 |
| 입력칸에서 `Backspace` | 노드가 안 지워진다 |
| 입력칸에서 `Ctrl+0` | 브라우저 페이지 줌으로 넘어간다 |

**스페이스는 한 겹 더 조심한다.** 버튼·링크의 기본 활성화 키라, 도구 모음 버튼에
포커스가 있을 때는 팬으로 가로채지 않는다. 그러지 않으면 키보드로 도구를 고를 수 없다.

---

## 아직 없는 것

혼동을 막기 위해 적어 둔다. 피그마에 있지만 **여기엔 아직 없다.**

- 더블클릭으로 안쪽 진입 (지금은 `Ctrl`+클릭만)
- `Tab`으로 형제 이동
- `Ctrl+D` 복제 · `Ctrl+C`/`Ctrl+V` 복사·붙여넣기
- `Shift+2` 선택 영역에 맞추기
- 방향키로 밀기 — 이 편집기는 좌표가 아니라 **레이아웃**으로 배치한다
- 다중 선택 — 선택은 한 번에 하나다
- 커서를 올렸을 때 잡힐 노드 미리 강조하기
- 자식 사이 간격 표시 · `Alt` 로 다른 노드까지 거리 재기
- 캔버스 우클릭 메뉴 — 브라우저 기본 메뉴를 막아 두기만 했다
