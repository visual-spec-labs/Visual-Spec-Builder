# 여러 탭의 자동저장 충돌 (#232)

같은 origin에서 같은 파일명을 연 탭은 하나의 프로젝트로 다룬다. 서로 다른 loopback
origin의 파일 저장도 서버 리비전 비교로 보호한다. 파일명이 없는 새 문서는 탭별 임시
식별자를 쓴다. opener에서 sessionStorage가 복사된 새 탭은 새 식별자를 받고 실제
새로고침은 기존 식별자를 유지한다. IR에 새 필드를 추가하지 않는다.

- 프로젝트별 localStorage 자동저장을 `storage` 이벤트로 감시한다. 쓰기 직전에도
  기준 원문을 비교한다. Web Locks로 비교와 쓰기를 탭 사이에서 직렬화한다.
  File → Save도 같은 잠금을 잡고 자동저장 리비전을 먼저 알린 뒤 HTTP 쓰기까지
  잠금을 유지한다. 500ms 안에 두 탭이 Save를 눌러도 오래된 쪽은 쓰지 않는다.
  Save as는 선택한 대상 파일의 자동저장과 충돌하면 쓰기 전에 거부한다.
- 다른 내용이 관측되면 자동저장과 File → Save/Save as를 중지한다. 현재 화면과
  메모리 초안은 유지하고 충돌 선택창을 띄운다. 취소는 저장 중지와 초안을 유지한다.
- **내 작업 별도 파일로 보관**은 검증된 JSON을 고유한 이름으로 다운로드한다.
  작업공간 파일을 쓰거나 현재 파일명을 바꾸지 않는다. 브라우저 다운로드 목록에서
  완료를 확인해야 한다. 다운로드만으로 자동저장이 재개되지는 않는다.
- **다른 탭의 최신 내용 불러오기**는 확인 후 선택 시점의 최신 자동저장을 읽고
  선택/Undo를 새 문서처럼 초기화한다. 읽기/검증 실패 시 초안과 저장 중지를 유지한다.
  다시 외부 변경이 생기면 다시 중지한다.
- 편집마다 sessionStorage에 탭별 복구본을 동기 기록한다. 충돌 중 새로고침해도
  다른 탭의 내용 대신 내 복구본과 중지 상태를 복원한다. 새로고침/닫기에서는
  경고를 요청한다. 500ms 대기 중인 편집이나 아직 시작 캐시에 기록되지 않은
  Save 내용도 종료 확인을 요청한다. 사용자 상호작용 없는 탭 등 브라우저가 경고를 생략할 수 있다.
- Web Locks가 없는 브라우저에서는 공유 자동저장을 쓰지 않고 안내한다. 세션 복구와
  별도 다운로드는 가능하며 작업공간 파일 쓰기는 안전하게 차단한다. sessionStorage 용량/접근 실패 시 종료 경고를 요청하지만
  브라우저 강제 종료, 저장소 삭제, 탭 폐쇄 이후의 세션 복원은 보장하지 않는다.

`visual-spec:project`는 이전 캐시와 새 탭의 시작점을 위한 호환 키다. 이미 열린 탭의
복구는 sessionStorage가 우선이므로 다른 프로젝트 탭이 이 호환 키를 바꿔도
내 초안을 교체하지 않는다. 프로젝트별 키에는 자동 삭제 정책을 추가하지 않았다.

자동저장 알림은 같은 origin의 앱 탭 사이에서 동작한다. 작업공간 파일 Save는
명시적인 디스크 저장이고, 감지된 충돌에서는 차단한다. 파일을 열 때 받은 디스크 리비전을 Save에 보내고 서버가 같은 잠금 안에서
현재 파일과 비교한다. 다른 origin/브라우저의 오래된 Save는 409로 차단된다. 이때
최신 불러오기는 로컬 캐시 대신 디스크를 다시 읽고 새 리비전을 채택한다.
리비전 없는 이전 캐시는 덮어쓰지 못한다. Export로 초안을 보존한 뒤 다시 열거나
새 파일명으로 Save as해야 한다. Save as는 기존 파일을 조용히 덮어쓰지 않는다.
앱 탭의 후속 Save는 진행 중인 HTTP 쓰기 완료까지 같은 잠금에서 기다린다.
외부 프로그램이 서버의 리비전 확인 이후 실제 쓰기와 경쟁하는 경우의 취소/되돌리기는
지원하지 않는다. 브라우저가 종료 확인을 생략하거나 사용자가 확인 후 탭을 닫으면
아직 내구 저장되지 않은 편집의 복구는 보장하지 않는다.

홈 이름 변경은 `publishProjectRename(oldFileName, renamedDiskSpec, newFileName)`으로
이전 파일명의 별도 `:rename` 알림 키에 새 경로를 알릴 수 있다. 기존 자동저장 내용은 쓰지 않는다. 다른 탭은 먼저 초안을 보관/취소할 수 있고,
최신 내용을 불러올 때만 새 저장 경로로 이동한다. 알림 리비전을 소비한 상태도
복구본에 기록하므로 이름을 원래대로 되돌리거나 이전 파일명을 다시 써도
과거 알림 때문에 계속 다른 경로로 이동하지 않는다.

검증: `test/spec-autosave.test.ts`는 대기 저장, 지연 이벤트의 쓰기 전 비교,
다른 프로젝트, 반복 충돌, 복구, 잘못된 최신 문서, 저장소 실패, 다운로드와 파일 저장
차단을 다룬다. 실제 Chromium 두 탭 검증은 PR에 별도로 기록한다.

2026-10-05에는 develop `8a4c8b6`을 정상 merge한 #258 코드에서 타입 검사·린트·빌드·
생성 타입 일치와 84파일 1,410테스트를 확인했다. 선택적 반응형 Chromium 테스트도
별도로 실행해 통과했다. 저장 회귀는 실제 Chromium에서 다음을 확인했다.

- 같은 origin 두 탭의 동시 Save: 디스크 승자와 패배 탭 초안 보존, 충돌창에서
  편집 단축키 차단, JSON 다운로드, 새로고침 복구, 최신 내용 채택.
- localhost와 127.0.0.1의 동시 Save: 서버 CAS가 한 쓰기를 거부하고, 패배 탭의
  최신 불러오기는 실제 디스크 내용과 리비전을 채택한다.
- Save as PUT에 507 실패를 주입하면 원본·초안이 유지되고, 내용을 수정한 뒤 같은
  대상 이름으로 다시 저장할 수 있다. 대기 PUT 중 다른 탭이 원본을 Save하면 대상
  경로를 채택하지 않고 원본 초안과 충돌 상태를 유지한다.
- storage 이벤트를 지연시키고 Open 읽기 중 다른 탭이 Save해도 적용 직전 검사로
  원래 문서·초안을 보존한다. 마지막 편집 직후 종료 확인과 새로고침 복구, 실제
  opener가 복제한 임시 탭의 독립 키와 재로딩 키 유지도 확인했다.
- localStorage/sessionStorage 용량 실패를 주입해 메모리와 원본 파일이 유지되고
  종료 확인이 요구됨을 확인했다. 강제 종료 후 복구를 보장하는 검사는 아니다.

로컬 이름 변경 성공 후에는 같은 잠금 안에서 `adoptRename(update)`로 표시 이름과
파일명을 함께 반영한다. 이 훅은 메모리 초안/Undo를 교체하지 않고 저장 기준만 옮긴다.
다른 탭은 별도 알림을 받고 중지된다. 파일명을 나중에 재사용했을 때 기존 자동저장과
새 디스크 문서가 다르면 보수적으로 충돌을 표시한다. 파일명 기반 정체성이므로 둘이
다른 프로젝트였는지는 추측하지 않는다. 이 경우에도 과거 이름 변경 경로로 자동 이동하지 않는다.

Save/Save as가 기다리는 동안 New/Open으로 문서가 바뀌면, 대기 중인 쓰기는 시작하지
않고 이미 시작된 스냅숏 저장의 완료가 현재 문서의 저장 경로를 바꾸지 않는다.
같은 문서의 계속된 편집은 초안에 남으며 Save as의 새 경로를 정상적으로 이어받는다.

## 비차단 문서 전환 (#302)

New/Open/홈 카드 열기는 `beginDocumentTransition()`을 비동기 읽기 **전에** 호출한다.
이 함수는 앞 전환 요청을 취소하고 문서 세대·documentId·spec 참조·파일명·디스크 리비전을 캡처한다.
전환 모듈은 spec/documentId/파일 메타데이터 변경마다 단조 증가하는 revision도 캡처한다.
따라서 Open 읽기 중 편집→Undo로 원래 spec 참조에 돌아와도 요청은 무효이고 redo를 보존한다.
같은 spec 참조를 loadSpec으로 다시 연 새 documentId도 이전 요청을 이어받지 않는다.
각 await 뒤 `current()`로 유효성을 확인하고, 적용 직전
`await transition.settle(nextFileName)`과 `current()`가 모두 참일 때만 동기적으로
`loadSpec`/`setFileName`을 실행한다. 대기 중 편집도 승인 대상이 달라진 것으로 취급한다.
같은 파일 재열기의 초안 비교 표식은 유효한 승인 뒤에만 설정한다.

`settle(nextFileName, signal?)`은 자동저장을 먼저 완료하고 필요한 경우 공통
PromptDialog의 확인 모달을 기다린다. 취소가 기본 포커스이며 Escape도 취소다.
요청 교체·문서 변경·autosave 중단·저장 충돌은 대기 승인을 취소한다. 승인 뒤에도
저장소를 다시 비교해 아직 이벤트가 도착하지 않은 다른 탭의 변경을 보호한다.
최신 요청 ID와 다른 오래된 UI 응답은 현재 모달을 닫거나 승인할 수 없다.

취소는 문서·선택·Undo·복구 초안을 변경하지 않는다. 계속하기는 기존 전환 의미를
유지하며, `discardDraft()`(이름 있는 파일의 열린 내용 채택)나 복구 초안 삭제를
호출하지 않는다. Home의 이름 없는 초안 목록·UUID 유지 재개·명시적 삭제는 #319의
별도 계약이다. 이 변경은 Home에서 이름 없는 초안을 다시 열 수 있다고 약속하지 않는다.

실제 Chromium 검증은 `scripts/browser/document-transitions.mjs`로 재현한다.
선택적 Playwright 설치 경로를 `PLAYWRIGHT_MODULE`, Chromium 경로를 `CHROME_BIN`에
지정한다. New/Open/카드 취소, 반복 요청, 오래된 승인, Tab/Shift+Tab·Escape·편집
단축키 격리, 대기 중 타이머·스크린샷 응답, 명시적 승인과 실제 두 번째 탭의 충돌을
확인한다. 기존 #332 회귀는 `scripts/browser/project-dialogs.mjs`를 함께 실행한다.
