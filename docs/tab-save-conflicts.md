# 여러 탭의 자동저장 충돌 (#232)

같은 origin에서 같은 파일명을 연 탭은 하나의 프로젝트로 다룬다. 파일명이 없는
새 문서는 탭별 임시 식별자를 쓴다. IR에 새 필드를 추가하지 않는다.

- 프로젝트별 localStorage 자동저장을 `storage` 이벤트로 감시한다. 쓰기 직전에도
  기준 원문을 비교한다. Web Locks로 비교와 쓰기를 탭 사이에서 직렬화한다.
- 다른 내용이 관측되면 자동저장과 File → Save/Save as를 중지한다. 현재 화면과
  메모리 초안은 유지하고 충돌 선택창을 띄운다. 취소는 저장 중지와 초안을 유지한다.
- **내 작업 별도 파일로 보관**은 검증된 JSON을 고유한 이름으로 다운로드한다.
  작업공간 파일을 쓰거나 현재 파일명을 바꾸지 않는다. 브라우저 다운로드 목록에서
  완료를 확인해야 한다. 다운로드만으로 자동저장이 재개되지는 않는다.
- **다른 탭의 최신 내용 불러오기**는 확인 후 선택 시점의 최신 자동저장을 읽고
  선택/Undo를 새 문서처럼 초기화한다. 읽기/검증 실패 시 초안과 저장 중지를 유지한다.
  다시 외부 변경이 생기면 다시 중지한다.
- 편집마다 sessionStorage에 탭별 복구본을 동기 기록한다. 충돌 중 새로고침해도
  다른 탭의 내용 대신 내 복구본과 중지 상태를 복원한다. 새로고침/닫기에서는
  경고를 요청한다. 사용자 상호작용 없는 탭 등 브라우저가 경고를 생략할 수 있다.
- Web Locks가 없는 브라우저에서는 공유 자동저장을 쓰지 않고 안내한다. 세션 복구와
  수동 저장/다운로드는 가능하다. sessionStorage 용량/접근 실패 시 종료 경고를 요청하지만
  브라우저 강제 종료, 저장소 삭제, 탭 폐쇄 이후의 세션 복원은 보장하지 않는다.

`visual-spec:project`는 이전 캐시와 새 탭의 시작점을 위한 호환 키다. 이미 열린 탭의
복구는 sessionStorage가 우선이므로 다른 프로젝트 탭이 이 호환 키를 바꿔도
내 초안을 교체하지 않는다. 프로젝트별 키에는 자동 삭제 정책을 추가하지 않았다.

이 기능은 같은 origin의 앱 탭 사이 자동저장 충돌을 다룬다. 작업공간 파일 Save는
명시적인 디스크 저장이고, 감지된 충돌에서는 차단한다. 외부 프로그램의 디스크 수정이나
다른 origin/브라우저의 동시 파일 저장까지 CAS/병합하는 기능은 아니다.
이미 진행 중인 HTTP 파일 쓰기를 취소하거나 되돌리는 기능도 추가하지 않는다.

홈 이름 변경은 `publishProjectRename(oldFileName, renamedDiskSpec, newFileName)`으로
이전 파일명의 별도 `:rename` 알림 키에 새 경로를 알릴 수 있다. 기존 자동저장 내용은 쓰지 않는다. 다른 탭은 먼저 초안을 보관/취소할 수 있고,
최신 내용을 불러올 때만 새 저장 경로로 이동한다.

검증: `test/spec-autosave.test.ts`는 대기 저장, 지연 이벤트의 쓰기 전 비교,
다른 프로젝트, 반복 충돌, 복구, 잘못된 최신 문서, 저장소 실패, 다운로드와 파일 저장
차단을 다룬다. 실제 Chromium 두 탭 검증은 PR에 별도로 기록한다.
