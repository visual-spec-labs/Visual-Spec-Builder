# 프로젝트 이름·파일명 변경 검증

2026-10-05, #259에 #258을 병합한 develop `515051c`을 정상 merge한 코드에서 검증했다.
이미 들어간 반응형·이미지 배경·삽입 메뉴·그룹화·Canvas 분리 기능은 유지했다.
TypeScript 테스트 프로젝트의 include/exclude 충돌은 양쪽 목록의 합집합으로 해결했다.

타입 검사·린트·production build·생성 타입 일치가 통과했다. 전체 Vitest는
86파일 1,456테스트 통과, 선택적 반응형 브라우저 테스트 1개 제외다.
#258의 실제 Chromium 저장 보호 8개 시나리오를 통합 코드에서 다시 실행해 통과했다.
[저장 충돌 기록](tab-save-conflicts.md)에 정상 동작과 실패 주입 범위를 설명한다.

추가 Chromium 검증:

- 이름과 실제 파일명을 변경하고 원래 이름으로 되돌렸다. 저장하지 않은 편집은
  메모리에 남고, rename은 디스크의 이름만 수정한다. 다른 탭은 초안을 보존하며
  중지한 뒤 최신 불러오기로 경로를 채택한다. 옛 알림으로 순환 이동하지 않는다.
- 기존 대상 파일에 대한 rename은 거부됐으며 양쪽 파일·초안이 유지됐다.
- 한글 84자 + `.json`(257바이트)은 요청 전 거부됐고, 한글 83자 + 영문 1자 +
  `.json`(255바이트)은 실제 파일로 생성됐다.
- localhost와 127.0.0.1에서 Save와 rename을 동시에 실행했다. 서버 CAS/잠금으로
  한 연산만 반영되고 오래된 연산은 원본 또는 초안을 보존했다.
- 대소문자가 다른 대상에 Save as와 rename을 경합시켜 대상 파일 하나만 생겼다.
  브라우저 잠금 키도 `Project.json`과 `project.JSON`이 동일함을 확인했다.
- rename 알림의 저장 공간 부족을 주입하면 HTTP 전에 실패하고 원본·초안이 남았다.
  409/500 rename 응답을 주입해 경로와 메모리 편집이 유지되는 것도 확인했다.
  불확실한 서버 실패는 디스크 성공을 주장하지 않고 확인을 요청한다.
- Save as PUT을 지연하고 Open으로 다른 문서를 연 뒤 완료시켰다. 새 문서 내용과
  파일명은 바뀌지 않았다. 이미 시작된 이전 스냅숏 쓰기를 취소한다는 뜻은 아니다.

서버 파일 쓰기 실패·원본 unlink 실패·rollback unlink 실패의 보존 경로는 기존
`test/workspace-middleware.test.ts`가 직접 오류를 주입해 검증한다. 브라우저 500 응답
검사만으로 실제 파일시스템 실패를 재현했다고 주장하지 않는다.
